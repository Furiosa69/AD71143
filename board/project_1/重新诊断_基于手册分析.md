# AD71143 LVDS时序分析与问题重新诊断

## 从规格书提取的关键信息

### Figure 37: DDR Mode LVDS Timing (Page 16)

根据规格书第16页的时序图，AD71143在DDR模式下：

#### 时序关系
```
DCLK:    由FPGA输出到AD71143
         ┌──┐  ┌──┐  ┌──┐  ┌──┐
         │  │  │  │  │  │  │  │
       ──┘  └──┘  └──┘  └──┘  └──

DOUT:    AD71143在DCLK的上升沿和下降沿都输出数据（DDR）
       ──D0──D1──D2──D3──D4──D5──
          ↑  ↑  ↑  ↑  ↑  ↑
        上升 下降 上升 下降 上升 下降
```

#### 关键参数（从手册推断）
- **tDO (Data Output Delay)**: DCLK边沿到DOUT有效的延迟
- **tSU (Setup Time)**: DOUT必须在采样前多久稳定
- **tH (Hold Time)**: DOUT必须在采样后保持多久

## 重新审视：我为什么判断是时序问题？

### 判断依据的重新梳理

#### 现象1: Lane A=0x00, Lane B=0xFF
这**不能直接**说明是时序问题，也可能是：
1. ❌ ~~时序问题~~ (我之前的假设)
2. ✓ **AD71143根本没输出数据**
3. ✓ **LVDS差分对硬件问题**
4. ✓ **配置寄存器错误**

#### 现象2: 修改采样方式后偶尔出现其他值
```
通道0: 0x0700 (偶尔)
通道2: 0x0380 (偶尔)
其他: 0x0000/0xFFFF (大部分时间)
```

这**确实像**时序不稳定，但也可能是：
- AD71143输出本身就不稳定（配置/供电问题）
- LVDS传输线路干扰

## 我犯的错误：过早使用IDELAYE2

### 问题

**IDELAYE2是解决已知时序偏移的手段，而不是诊断工具。**

在没有确认以下问题之前，不应该直接用IDELAYE2：
1. ✗ 是否确认AD71143真的在输出数据？
2. ✗ 是否用示波器测量过DOUT波形？
3. ✗ 是否确认DCLK频率和相位正确？
4. ✗ 是否尝试过LFSR测试模式验证接口？

---

## 正确的诊断流程应该是

### 第1步：启用LFSR测试模式 ⭐⭐⭐

这是AD71143手册**明确推荐**的数字接口完整性检查方法！

```verilog
// top.v:518 修改
(cfg_reg_idx == 4'd11) ? 10'h040 :  // Reg11: LFSR_EN=1 (启用测试模式)
```

**LFSR的作用**：
- AD71143输出已知的伪随机序列
- 不依赖模拟前端（探测器可以不接）
- 纯数字信号，便于验证LVDS接口

**预期结果**：
- 如果LFSR数据正常接收 → LVDS接口OK，问题在模拟前端
- 如果LFSR数据仍然是0x0000/0xFFFF → LVDS接口有问题

### 第2步：硬件测量（如果有示波器）

测量以下信号：
```
1. DCLK差分对 (dclk_p_A1, dclk_n_A1)
   - 应该看到100MHz差分方波
   
2. DOUT差分对 (dout_p_A1, dout_n_A1)
   - 应该看到高速数据翻转
   - 在DCLK边沿时刻切换
```

### 第3步：检查DCLK频率

在ILA中验证DCLK是否真的是100MHz：
```verilog
// 添加计数器测量DCLK周期
reg [15:0] dclk_period_cnt;
```

### 第4步：如果上述都正常，才考虑时序微调

到这一步才能确定是setup/hold time不满足，才需要IDELAYE2。

## 时序问题的真正证据（手册中的隐含要求）

### 从Figure 37推断的时序约束

虽然手册没有明确给出tSU/tH数值，但DDR模式下：
```
DCLK周期 = 10ns (100MHz)
半周期 = 5ns

合理的时序裕量：
tSU + tH < 5ns（半周期内）
tDO < 2ns（AD71143输出延迟）

采样窗口 ≈ 5ns - 2ns = 3ns
```

**如果FPGA直接在DCLK边沿采样**：
- 采样点正好在数据切换时刻
- 亚稳态风险高
- 需要延迟调整

但这是**理论分析**，不是诊断依据。
