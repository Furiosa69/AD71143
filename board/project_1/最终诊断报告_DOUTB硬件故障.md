# 最终诊断报告：DOUTB硬件故障

## 问题确认

通过ILA和万用表测量，确认问题：

```
FPGA引脚B20 (dout_p_B1/DOUTB+) = 0V      (一直低电平)
FPGA引脚A20 (dout_n_B1/DOUTB-) = 2.5V    (一直高电平)

IBUFDS差分接收：
  输入: P=0V, N=2.5V
  差分电压 = P-N = -2.5V (负值)
  输出: dout_b_raw = 1 (逻辑高)
```

这解释了为什么：
- Lane B数据一直是0xFFFF
- 奇数通道(1,3,5,7)无数据

---

## 根本原因

**AD71143芯片的DOUTB差分输出驱动器故障**

正常情况下：
- DOUTB+和DOUTB-应该在0~2.5V之间高速翻转（~100MHz）
- 当前：DOUTB+固定0V，DOUTB-固定2.5V

---

## 对比正常的DOUTA

Lane A (DOUTA) 工作正常：
- dout_a_raw有0/1变化
- 偶数通道(0,2,4,6)能接收到数据（虽然不稳定）

说明：
- ✓ FPGA的LVDS接收正常
- ✓ AD71143的DOUTA正常
- ✗ AD71143的DOUTB损坏

---

## 可能的损坏原因

### 1. 静电损坏
LVDS输出对静电敏感，可能在安装/调试时损坏

### 2. 芯片内部缺陷
DOUTB通道的差分驱动器失效

### 3. 供电异常（需要验证）
如果VDDIO电压不稳定，可能导致输出异常

---

## 诊断建议

### 立即检查（用示波器）

**在AD71143芯片引脚上直接测量**（不是FPGA侧）：

```
位置：AD71143的DOUTB+和DOUTB-引脚

正常应该看到：
  - 高速数据翻转（~100MHz方波）
  - DOUTB+和DOUTB-反相

如果仍然是0V和2.5V固定电平：
  → 确认芯片DOUTB损坏
```

### 检查供电（用万用表）

测量AD71143的电源引脚：
```
VDD (模拟电源)   = 3.3V (±5%)
VDDIO (数字IO)   = 2.5V 或 3.3V (±5%)
VREF (参考电压)  = 应该稳定，无纹波
GND              = 0V
```

如果供电异常，可能影响DOUTB输出

---

## 临时解决方案

### 方案A：使用Panel 0
如果Panel 0的AD71143 DOUTB正常，可以：
- 只使用Panel 0采集数据
- 修改代码输出Panel 0而不是Panel 1

### 方案B：单LVDS模式（带宽减半）
将AD71143配置为单LVDS输出：
```verilog
// Reg2: DOUTMODE=0 (只用DOUTA)
(cfg_reg_idx == 4'd3) ? 10'h025 : // DOUTMODE改为0
```

缺点：
- 只能输出128个通道（原本256个）
- 数据率减半

### 方案C：更换AD71143芯片
如果确认芯片损坏，需要更换
