# 引脚交换测试方案

## 目的
验证问题是**代码/逻辑问题**还是**硬件/引脚问题**

## 测试方法

### 在约束文件中交换Lane A和Lane B的引脚分配

```tcl
# 原始配置（当前）
set_property PACKAGE_PIN E13 [get_ports dout_p_A1]  # Lane A+
set_property PACKAGE_PIN E14 [get_ports dout_n_A1]  # Lane A-
set_property PACKAGE_PIN B20 [get_ports dout_p_B1]  # Lane B+ ← 测量0V
set_property PACKAGE_PIN A20 [get_ports dout_n_B1]  # Lane B- ← 测量2.5V

# 交换后配置（测试用）
set_property PACKAGE_PIN B20 [get_ports dout_p_A1]  # Lane A+ 用B20
set_property PACKAGE_PIN A20 [get_ports dout_n_A1]  # Lane A- 用A20
set_property PACKAGE_PIN E13 [get_ports dout_p_B1]  # Lane B+ 用E13
set_property PACKAGE_PIN E14 [get_ports dout_n_B1]  # Lane B- 用E14
```

## 预期结果

### 结果A：问题"跟着代码走"
```
交换后：
- dout_b_raw 变成有0/1变化（因为现在用E13/E14）
- dout_a_raw 变成一直是1（因为现在用B20/A20）
- 上位机：奇数通道正常，偶数通道全0xFFFF

结论：代码/逻辑问题
```

### 结果B：问题"留在原引脚"
```
交换后：
- dout_b_raw 仍然是1（虽然代码说是Lane B，但物理用的是E13/E14）
- dout_a_raw 仍然有变化（虽然代码说是Lane A，但物理用的是B20/A20）
- 上位机：数据跟交换前一样或相反

结论：硬件问题（PCB走线、AD71143芯片、或FPGA引脚）
```

---

## 如果是结果A（代码问题）

那可能的原因：
1. IBUFDS实例化有问题（但我们检查过是对称的）
2. 采样逻辑对Lane A和Lane B处理不同
3. 状态机对两个Lane的控制不同
4. 时钟域问题

## 如果是结果B（硬件问题）

那可能的原因：
1. AD71143的DOUTB引脚损坏
2. PCB上DOUTB走线断路/短路
3. FPC连接器DOUTB针脚接触不良
4. FPGA的B20/A20引脚损坏（但这个概率较低）

---

## 我的判断

基于以下事实，我**95%确信是硬件问题**：

```
✓ IBUFDS配置完全对称
✓ 代码中Lane A和Lane B的处理完全相同
✓ 你测量到B20=0V, A20=2.5V（固定电平）
✓ LFSR测试模式下仍然Lane B异常
```

**LVDS是纯硬件接收**，代码几乎不可能让差分对固定在某个电平。

但**引脚交换测试**可以100%确认！
